## Findings fixed in this audit

### 1. Copilot authorization over-grant

**Risk:** the Copilot Postgres store previously treated `inbox.read` as the effective permission for all non-owner/non-admin Copilot operations. A custom role with read-only inbox access could therefore reach configuration/handoff/approval mutation paths.

**Fix:**
- tenant reads require `inbox.read`;
- handoff decisions require `inbox.respond`;
- Copilot configuration and tool-approval decisions require new `copilot.manage`;
- owners/admins retain the existing trusted management path;
- `copilot.manage` was added to the custom-role permission catalog and command-center permission UI;
- regression tests prove a read-only custom role cannot perform these mutations.

### 2. OpenAI-compatible SSE EOF loss

**Risk:** a provider stream ending on an unterminated final SSE line could drop the final model delta.

**Fix:** the adapter now parses complete SSE lines and explicitly flushes the remaining decoder/buffer at provider EOF. Regression coverage verifies a final delta without a trailing newline and terminal/EOF markers.

### 3. CI coverage drift

**Fix:**
- CI now runs `capabilities:check` and `service:check`;
- the preview artifact name was updated from V148 to V153.

### 4. README release-status drift

**Fix:** the old V126 block is now clearly historical, and the production-readiness section reflects the current V153 Copilot/webchat boundary instead of presenting V126-era capabilities as current.

## Audit conclusion

Atlas V153 is substantially beyond a prototype at the contract/runtime level. The material correctness issues found in this pass were authorization over-granting, model-stream EOF loss, CI gate drift, and release-documentation drift; those were addressed on the audit branch and covered by automated checks.

The next development phase should add product capabilities on top of this hardened boundary rather than rebuilding the core architecture.
