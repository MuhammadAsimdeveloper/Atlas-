ATLAS V112.0.0 — PostgreSQL Identity and Tenant Foundation

Implemented
- Authenticated account API: signup, email verification/resend, password sign-in, reset/logout, profile, workspace create/select, team list, invitation create/accept and tenant custom-role list/create.
- PostgreSQL identity and multi-tenancy schema with forced row-level security, one-use hashed tokens, opaque sessions, tenant-scoped membership/invitations/roles, shared auth rate limits and append-only audit events.
- Platform-owner authority remains only a server-resolved verified email for Khan. No company role, signup field or request property can grant global access.
- Responsive same-origin workspace web UI with real member/invitation/audit dashboard counts, and clear unavailable labels for disconnected CRM, AI/agents, workflow, messaging and revenue modules.
- Migration runner with advisory lock, checksum records and separate migration/runtime database connections. Production readiness queries PostgreSQL and checks the V112 identity schema.
- Production API and migration database pools enforce TLS certificate verification, ignore URL-level TLS downgrades, support a mounted private CA and bound pool size. Runtime-role grants reject superuser, BYPASSRLS, role inheritance and ownership of tenant identity tables.
- Rate-limit and IP identifiers use HMAC-SHA-256 keyed by the server secret. The full migration chain exposed and fixed a reserved identifier in V90 and an unavailable JSON helper in V96.
- Production authentication throttling requires a valid edge-supplied client IP. Duplicate signup races remain enumeration-safe; each tenant/email may have only one pending invite, and superseded invitations are accurately shown as replaced.
- PGlite migration/RLS integration test and HTTP authentication end-to-end tests. Node-postgres is a pinned runtime dependency; PGlite is test-only.
- Current official HighLevel/n8n findings are documented in docs/V112-IDENTITY-TENANT-FOUNDATION.md.
